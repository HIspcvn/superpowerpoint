# Validation record

Validation date: 2026-09-24. This report separates package checks, code tests, rendered output and actual application use.

## Automated tools

The Python test suite ran on Windows with Python 3.13.7: **47 cases, 46 passed, 1 skipped**. The skipped case requires permission to create a Windows symbolic link. Tests cover inspection failures, authoritative package entry and presentation order, notes, native chart/table evidence, embedded-image relationships, read limits, source immutability, safe installation without generated bytecode, and metadata/link validation.

The GitHub Actions workflow is configured for Windows and Ubuntu with Python 3.10 and 3.13. Those remote jobs have not run during this local implementation.

The actual six-skill collection was also copied by the installer into an ignored local smoke-test directory. Its installed inspector successfully checked the shipped sample, confirming sibling resources and the nested executable are included. This test installation does not register the skills globally or publish the plugin.

The project supplies a standard-library repository validator. The installed skill-creator `quick_validate.py` and plugin-creator `validate_plugin.py` could not run because their optional PyYAML dependency is absent in this environment. Project validation is a separate implementation; it does not imply those upstream validators ran successfully.

## Sample deck

The [sample](../examples/demo/output/superpowerpoint-demo.pptx) contains four slides, a native chart on slide 2, a native table on slide 3 and speaker notes on all four slides. The portable inspector reports no errors or warnings for these declared requirements.

The host Presentations finalizer independently passed package integrity, declared dimensions, font policy, native table presence, chart/workbook value correspondence and reimport of the exported PPTX. This establishes structural evidence, not native PowerPoint behavior. The sample table contains text, so arithmetic validation was correctly inapplicable. The chart values 24, 36 and 48 are visibly identified as synthetic.

All four final PPTX slides were reimported and rendered with `@oai/artifact-tool` 2.8.59, then individually inspected at 1280 × 720. The stored previews show readable Vietnamese diacritics, complete table rows and matching chart labels without observed clipping or unintended overlaps. Microsoft PowerPoint and Google Slides were not opened; editing, playback and fidelity in those applications remain untested.

## Optional rendering runtime

On the supplied Windows Node 24.19.0 runtime, rendering writes complete PNGs but the native process later exits with `0xC0000409`. A minimal reproduction isolated this to the rendering path: importing the same PPTX without rendering exits 0. Limiting renderer threads or selecting CPU canvas did not resolve the native teardown failure, and no supplied runtime files were changed.

The demo now separates PPTX authoring/finalization from optional `--render`. The default builder was rerun in a fresh output directory and exited **0**, with finalizer evidence and a valid four-slide deck. It does not hide rendering failures or claim rendering happened when the option is omitted. Previews from the earlier render are included and reviewed; they do not establish a clean renderer process exit.

## Behavioral and independent review

Six realistic evaluation cases are supplied in [evals/scenarios.json](../evals/scenarios.json). They are not part of unit-test execution. A separate reviewer inspected all six skills, references and portable tools. It identified two inspector defects: accepting a missing root officeDocument relationship and silently ignoring malformed embedded-image relationships. Both received focused regression work before final verification. It found no concrete authorization or preservation defect in the skill instructions and no actionable installer issue.

A separate read-only behavioral execution used the router skill and a temporary copy of the sample. The agent correctly read slide 2's speaker notes, answered in Vietnamese that the values were synthetic, and verified the source SHA-256 did not change. This exercises the `read-only` scenario. The other five scenarios, baseline comparison without the skills, and agent-driven end-to-end creation/editing scenarios have **not run**. The sample builder integration and code review do not substitute for those behavior evaluations.

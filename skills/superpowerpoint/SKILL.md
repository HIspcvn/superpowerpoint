# Superpowerpoint

Translate the user's presentation request into an editable, checked deliverable. Match the work to the request: a correction does not need a new narrative, and a planning request does not authorize building or publishing a deck.

## Choose the work

These six skills are installed together as sibling folders. Read only the skills needed for the task:

| Request | Entry point |
| --- | --- |
| Turn an idea, document, or data into a presentation plan | [planning-powerpoint](../planning-powerpoint/SKILL.md) |
| Establish visual direction or adapt a brand/template | [designing-powerpoint](../designing-powerpoint/SKILL.md) |
| Create or rebuild editable slides | [building-powerpoint](../building-powerpoint/SKILL.md) |
| Change an existing presentation | [editing-powerpoint](../editing-powerpoint/SKILL.md) |
| Assess quality or verify a completed deck | [reviewing-powerpoint](../reviewing-powerpoint/SKILL.md) |

For a new deck, normally connect planning → design → build → review. Reuse a supplied brief, approved storyboard, or template instead of recreating it. For a small edit, go directly to editing and proportionate review; keep the existing story and design.

## Work contract

- Extract the audience, desired outcome, content, language, delivery setting, format, and constraints from the conversation and supplied files. Ask only about unknowns that materially change the work. For reversible choices, state a reasonable assumption and continue.
- Honor permission to complete the full task. Do not add approval gates between stages when the user has already asked for execution. Pause only for a necessary answer or an actual authorization boundary.
- Respond in the user's language. Vietnamese briefs and Vietnamese slide content are supported; preserve diacritics, proper names, locale-specific numbers, and the requested language throughout.
- Keep the user's requested slide count, ratio, brand, template, and level of editability. Do not impose a cover, agenda, conclusion, or fixed number of slides.
- Separate supplied facts, researched facts, and assumptions. Preserve source provenance and never invent results, quotations, or metrics to fill a slide.
- Prefer editable text, shapes, charts, and tables. Do not disguise a screenshot of a slide as an editable deck. Explain specific editability exceptions.

## Evidence before completion

Deliver the requested artifact with concise validation evidence. A successful export proves neither legibility nor correct PowerPoint playback. Render every slide and inspect the images; run applicable package checks; report actual PowerPoint opening or playback only when performed. If an environment cannot complete a check, state the precise gap and deliver the best supported result without claiming that check passed.

Load detailed runtime guidance only when choosing an authoring or rendering path: [capability and runtime adapters](../building-powerpoint/references/capability-adapters.md).

# Brief and storyboard handoff

Use the fields that change the actual deck. A brief can be five sentences; do not make the user complete a form when the conversation already contains the answers.

## Brief

| Field | Example |
| --- | --- |
| Audience and decision | Operations leaders choosing a pilot for faster onboarding |
| Core message | Test the proposed onboarding checklist before a wider rollout |
| Setting and length | Live discussion; 5 slides; 6 minutes |
| Language and tone | Vietnamese, concise, neutral business language |
| Sources | Supplied interview summary, pages 2–4; approved pilot proposal |
| Constraints | Supplied 16:9 template; editable tables; no invented impact figures |
| Assumptions | Audience knows the current workflow; pilot has no approved budget yet |
| Deliverable | Editable PPTX and preview PDF if supported |

## Storyboard

This is an example of a plan, not a required five-slide structure. Its hypothetical context does not supply facts for another deck.

| Slide | Purpose and draft title | Evidence/content | Visual and build notes |
| --- | --- | --- | --- |
| 1 | Frame the decision: “Chọn phạm vi thử nghiệm quy trình tiếp nhận” | The pilot decision stated in the approved proposal | Existing title layout; three short decision criteria |
| 2 | Explain the current problem: “Các điểm gián đoạn trong quy trình hiện tại” | Only themes supported by the interview summary; cite exact pages | Editable process map; distinguish observations from interpretation |
| 3 | Describe the proposed change: “Danh sách kiểm tra thống nhất cho từng bước” | Checklist fields from the proposal | Before/after workflow using native shapes; label as proposed |
| 4 | Define the pilot: “Thử nghiệm với phạm vi và chỉ số rõ ràng” | Approved scope and measurement definitions; budget marked “Chưa xác nhận” | Native table; keep units and responsible roles explicit |
| 5 | Request the decision: “Thống nhất phạm vi và người phụ trách” | Decision options and named roles only if supplied | Editable decision list; no promised outcomes without evidence |

For quantitative slides, append the actual values, units, period, population, and source locator. For example: `slide 4; source pilot.xlsx, Metrics!A1:D8; duration in business days; missing values stay missing`. A chart image alone is not sufficient data provenance.

## Source ledger

Record a short ID, retrievable locator, supported claim/data, date or reporting period when relevant, and usage status. Use those IDs in the storyboard and translate them into readable citations in slide footnotes, speaker notes, or a source appendix suited to the user's format. The final artifact should retain useful source access; do not leave the ledger only in private working notes.

Track unresolved items explicitly: owner or source needed, the affected slide, and whether the deck can proceed with a labeled assumption. Ask only when the answer changes the argument or deliverable materially.

# Planning PowerPoint

Create a usable content plan that the builder can execute without inventing the argument or missing data. Keep planning proportional to complexity; a short, clear request may need only a compact outline.

## Establish the brief

Extract what is already known: audience, action or decision, setting, language, slide/time budget, content sources, brand/template, and final formats. Ask only about material unknowns. Carry explicit assumptions forward so later stages do not quietly treat them as facts. Honor existing permission to execute after planning.

Read [brief and storyboard examples](references/brief-storyboard.md) when a reusable handoff or complex narrative is useful.

## Build the argument

1. Write the central message and the audience's next action. Organize the story around what the audience needs to understand or decide.
2. Inspect supplied documents and data before outlining claims. Keep a source ledger with file/page, sheet/range, URL/date, or another retrievable locator as applicable. Research missing external claims only when needed and with available tools.
3. Give each slide a purpose, a claim or useful title, supporting evidence, and a suitable visual. Use a descriptive title when the evidence does not support a conclusion.
4. Check narrative order, repeated content, unsupported jumps, and whether the content fits the requested slide count and presentation time. If constraints conflict, identify the concrete tradeoff and use the best available evidence.

Use placeholders only for genuinely missing input, clearly labeled as missing or illustrative. Never manufacture company results, percentages, quotations, or citations. Distinguish an example dataset from observed results.

## Handoff

For a substantial deck, save a brief and storyboard in the project output folder so design, build, and review share the same content contract. Include each slide's source locators and any chart values or table fields needed to build it. Use ordinary prose or a compact table rather than a schema unless automation needs one.

Preserve the requested language, including Vietnamese diacritics and local terminology. Do not translate supplied proper names without reason. Do not add conventional slides merely to fill a template.

If execution is requested, continue to [designing-powerpoint](../designing-powerpoint/SKILL.md) or [building-powerpoint](../building-powerpoint/SKILL.md) when an adequate visual contract already exists. If the user requested only a plan, stop at the plan.

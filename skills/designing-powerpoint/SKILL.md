# Designing PowerPoint

Create a visual contract that makes the planned content readable and consistent. Preserve a supplied template unless redesign is in scope. Do not replace the user's brand with a generic style.

## Inspect the starting point

Read the brief/storyboard and inspect representative template slides, masters, layouts, fonts, theme colors, logos, recurring elements, and aspect ratio. Render supplied slides when possible; file internals alone cannot establish visual fidelity. A PDF or image reference can guide appearance but does not provide native editable objects.

Read [the design contract](references/design-contract.md) for the fields and visual decisions to record. If an existing deck already has a coherent contract and the task is a small edit, preserve it and continue to [editing-powerpoint](../editing-powerpoint/SKILL.md).

## Make the content fit

- Give each slide one clear focal point and a deliberate reading order. Choose layouts around its message and evidence.
- Select fonts available in the target environment, with glyph coverage for the requested language. For Vietnamese, check diacritics in actual rendered text. Record substitutions that affect fidelity.
- Keep type sizes readable for the delivery setting. Shorten or reorganize dense content before shrinking type. Split content only when consistent with the requested scope and slide count.
- Assign stable roles to colors, font levels, spacing, and chart series. Use adequate contrast and avoid relying only on color for meaning.
- Choose chart forms that answer the audience's question; make units, periods, baselines, and data labels clear. Use a table when exact lookup is more important than a pattern.
- Use native text, shapes, charts, and tables for editable content. Place raster imagery only where it is the appropriate medium, with sensible cropping and resolution.

For a substantial new visual direction, build and render one or two representative slides that exercise the hardest layout before scaling the design. This is an internal check, not an automatic approval gate.

## Handoff

Record the visual choices, reusable layouts, template restrictions, and any font or asset limitations beside the storyboard. Continue to [building-powerpoint](../building-powerpoint/SKILL.md) when execution is authorized. Verify the exported appearance again through [reviewing-powerpoint](../reviewing-powerpoint/SKILL.md); a promising design specification is not evidence that the final deck renders correctly.
